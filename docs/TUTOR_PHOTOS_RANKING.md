# 家教照片与量化匹配

## 基线与需求取舍

本轮以 2026-10-21 的 `main` 为基线。此前 #16 模型需求解析已合并，主分支还有学习中心、地图选点与课次/作业。家教申请原本只存文字与参考价格；匹配仅按科目、方式、价格余量和关键词排序。本轮保持入驻、审核、预约及模型解析入口不变，扩展老师资料与规则评分。

## 照片流程

家教先保存草稿，再在入驻页用 `uni.chooseImage` 选择 JPG/PNG/WebP。API 模式经带会话令牌的 `uni.uploadFile` 发送到 `POST /api/tutor-applications/photo`；服务端限制 2 MB 和 1200 万输入像素，使用 `sharp` 校正方向、缩至最多 512×512，并转成 JPEG（默认移除 EXIF 等元数据）。随机文件名保存在服务端私有 `TUTOR_PHOTO_ROOT` 目录，仅数据库保存引用。`sharp` 是此处新增的唯一运行时依赖，用于格式解码、压缩及清除原图元数据。

本人申请与管理员详情返回已授权的预览 data URL。公开 `/api/tutors/:id/photo` 仅在家教资料已发布且关联申请已批准时返回图片；其他状态返回 404。上传或更换已批准照片会撤回公开资料，家教重新提交、管理员审核通过后才可公开。前端老师卡片和详情在无照片时继续使用姓名首字占位。Mock 模式照片保存在本机申请数据中，限制 600 KB，不跨设备同步。

演示审核只检查申请流程和可见内容，**不证明**照片属于该家教、本人身份或教学资质。请勿上传学生照片、证件或真实未成年人的资料。正式使用前需建立本人授权、内容审核、删除请求、备份/清理和对象存储策略；数据库备份应与私有照片目录一起保存。后端仍拒绝 `NODE_ENV=production` 启动。

## 评分因子

科目、预算上限、授课方式、附近半径继续作为硬条件。仅对符合条件的资料计算六项排序分，默认权重合计 100：教学经历 30、相关课程成绩 20、教学能力 20、匿名案例数 15、偏好契合 10、价格余量 5。家长可以在匹配页拖动每项 0–50 的滑块；权重总和只需大于零，计算时归一化。零权重表示该因子不参与排序。当前设置只保留在本次页面会话，不写入数据库。

| 因子 | 自述资料与比例 |
| --- | --- |
| 教学经历 | `min(月数 / 36, 1)`；可填 0–120 月 |
| 相关课程成绩 | `成绩 / 100`；可填 0–100 分 |
| 教学能力 | `自评 / 5`；可填 0–5 |
| 匿名案例数 | `min(数量 / 10, 1)`；可填 0–50；摘要最多 120 字，不写学生信息 |
| 偏好契合 | 资料关键词命中数 / 去重偏好词数；空偏好为 0 |
| 价格余量 | `max(0, 1 − 课时费 / 预算)`；只在预算硬条件通过后计算 |

每项贡献为 `round(100 × 当前权重 / 总权重 × 比例)`，合计最多 100；缺失资料记 0，不推断成绩或经历。同分沿用片区参考距离、价格、ID 的稳定顺序。默认价格评分只占 5%，但预算上限仍严格筛掉超价家教。页面展示逐项理由。自述成绩、能力、经历和案例**未经证据核验**，分数不是教学效果或真实能力评价。正式运行前应确定可核验指标、反作弊规则、学生反馈采样和偏差评估。

## API 与兼容

`Tutor` / `TutorApplication` 增加可选字段 `photoUrl`、`experienceMonths`、`academicScore`、`teachingSkillLevel`、`caseCount`、`caseSummary`。旧记录迁移后数值为 `null`、摘要为空；旧客户端省略字段仍可提交，新客户端用 `null` 显式清空数值字段。照片文件不进入 JSON 提交，也不进入仓库。公开 Tutor 只返回已审核照片的相对 URL；管理员/家教申请详情的预览是 data URL。详见 [API 契约](API_CONTRACT.md)。

## 验证边界

单元测试覆盖可调权重、低价与经历排序、缺失证据、非法权重；后端测试覆盖迁移、图片权限、文件类型、待审禁止修改、审核后公开、修改后撤回及重新批准。H5/微信小程序构建和浏览器交互结果以 PR 测试记录为准；微信真机相册/相机交互需要 AppID 和设备，未在 CI 中自动验证。
