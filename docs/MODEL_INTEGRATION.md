# 可选模型需求解析

## 接入位置

现有推荐先按科目、预算和授课方式过滤，再按公开公式排序。模型只把用户主动提交的一段自然语言需求转换为表单建议；用户确认后才填入表单，仍需点击“生成推荐”。模型不读取家教资料、预约、账户 ID 或联系方式，不生成家教名单或分数。Mock 模式与未配置模型的 API 模式继续使用原规则。

方案取舍：托管的兼容 Chat Completions 服务接入快，但需要密钥、预算和供应商数据处理评审；本机兼容服务无需外部密钥，但需要自备推理资源，响应速度取决于设备。两者使用同一服务端接口。小程序直接调用模型会暴露凭据，因此没有采用。让模型直接替代硬过滤或家教排序会削弱现有可解释、可复测的业务约束，因此模型仅处理文本到表单的转换。

后端 `server/src/match-model.ts` 封装兼容 Chat Completions 的请求；`POST /api/match-assistant/parse` 要求家长/学生开发账户，`GET /api/match-assistant/status` 仅报告是否已配置。成功格式为 `{ "data": { "subject", "grade", "budget", "mode", "preference" } }`，未识别字段为 `null`。服务端校验允许的科目、演示年级、0.01–2000 元预算、授课方式及 40 字以内的偏好；不接受额外字段。上游失败或无效输出返回明确错误，不伪造成功结果。

## 本机配置

1. 按 README 启动开发后端和 API 模式前端。
2. 在未提交的 `server/.env` 中设置 `MATCH_MODEL_BASE_URL`（例如 `https://你的服务商.example/v1`）、`MATCH_MODEL_NAME`（该服务提供的 Chat Completions 模型名称）和 `MATCH_MODEL_API_KEY`。远端地址必须是 HTTPS；本机 `http://localhost` 或 `http://127.0.0.1` 兼容服务可不设密钥。可选 `MATCH_MODEL_TIMEOUT_MS`，实际限制在 1000–15000 毫秒。
3. 重启后端，访问 `/api/match-assistant/status` 应返回 `enabled: true`。这只表示配置齐全，**不是**供应商连通性或模型质量检查。
4. 以家长开发账户登录，在家教匹配页输入不含个人信息的需求并点击“解析需求”，核对建议、确认填入，最后使用原规则生成推荐。

不要将密钥放进前端 `VITE_*` 环境变量、仓库、截图或客户端请求。不要把真实未成年人资料发送给演示模型。当前服务在 `NODE_ENV=production` 拒绝启动；供应商使用条款、数据保留、计费、监控和生产限流需在真实试运营前评审。

## 边界和验证

- 请求最多 160 字；服务端拦截常见手机号、邮箱、身份证号及地址/联系方式关键词。这是基础防误填，**不能保证识别所有个人信息**。前端明确提示并由用户主动发起；平台不保存需求文本。
- 每个账户每分钟最多 10 次、每个来源每分钟最多 30 次模型解析；单进程内存限流，仅适合开发演示。上游请求限制输出长度、响应大小和超时；不记录密钥或上游原始错误。
- 自动化测试使用虚构模型响应，覆盖权限、输入拦截、限流、输出校验和异常；API 模式桌面与手机浏览器测试验证登录引导、建议确认及后续规则推荐。没有配置真实模型密钥，因此真实供应商调用、成本和微信真机交互**未验证**。
- 微信小程序调用的是本项目后端，仍需 HTTPS、合法请求域名和测试 AppID；小程序里不配置模型密钥。
