```mermaid
flowchart LR
  A[首页搜索与 AI 入口] --> B[匹配需求表单]

  C --> D[BusinessService.listTutors 分页]

  H --> I[现有家教详情 → 现有预约]
```

## 数据与接口

D 新增 `src/services/matching.ts`，与身份、预约、家教类型解耦。调用 A/B/C 已有异步业务契约，不更改家教/预约类型、不创建孤立的老师列表。完整分页读取 50 条/页，按 ID 去重；100 页上限明确报错；网络中断不返回半成品或冒充 API 的虚构结果。结果链接使用实际 `tutor.id` 进入原详情与预约。

年级仅为演示摘要。输入不含学生姓名、联系方式、学校等敏感信息，不保存匹配需求，不发送给第三方模型。偏好只按公开简介、专业、地区、标签匹配，最多 40 字，以空格或中英文标点分词并去重。不宣称理解复杂语义。

## 规则与解释

1. 必填：受支持的科目、演示年级；预算必须为 0.01–2000 元的十进制数字，最多两位小数。
2. 硬过滤：科目包含；课时费不超过预算；方式相同或家教支持“均可”（用户“均可”接受任意方式）。不自动提高预算或放宽条件。
3. 得分：科目 50；兼容方式 20；预算余量 round(20 × (1 − 价格/预算))；偏好 round(10 × 命中词数/去重词数)，空偏好为 0。每项理由展示实际字段及所得分。
4. 同分依次按课时费升序、ID 字典序；分数是规则排序值，不是成功概率、能力分或效果保证。预算余量偏向低价，因此推荐不代表质量排名。
5. 空结果同时给出各类排除数（按科目→预算→方式的首个失败条件统计），引导用户自行调整条件。

## 可展示的创新

- 可解释需求撮合：把需求、过滤、计分和推荐理由同时展示，避免“黑箱”演示。
- 无密钥可复现：确定性规则支持离线 Mock 备份，未接入大模型时明确展示“规则演示”。未来模型只可用于可选的需求解析，核心过滤应继续可测试。
- 推荐与业务闭环：同一服务源，推荐结果直接进入预约；审核后的公开家教与匹配数据一致。

这些是本项目实现特点，不声称行业首创。尚无真实用户实验、匹配准确率、学习效果或商业收入证据。大模型、真实微信认证、真实资质核验、支付与通知不在已完成范围。
