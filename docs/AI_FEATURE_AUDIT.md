## 本批已处理的问题

1. 学习中心未接入当前主线：兼容整合 #22 与 #23，首页/公共导航都有入口。新入口在桌面占满一行，手机可正常换行。
2. 知识点到匹配的上下文丢失：从笔记/试卷找老师时只传白名单主题 ID，带入科目、学段并显示知识点；仍要求手填预算。不支持的科目保持空白并明确提示，不偷换成数学。返回可恢复原知识点。
3. 解析结果与应用不一致：未识别字段显示空时，确认后也清空；防止上一份需求的预算、科目或授课方式悄悄保留。
4. 过期异步结果：离开页面后忽略旧解析/推荐响应；修改位置后不把旧推荐回填，异步结束可恢复按钮状态。
5. 模型配置状态文案：配置存在只表示“已配置”，不在发起请求前声称已使用模型。

用户点位、练习作答、成绩和个人资料不加入知识点跳转 URL，也不自动发送给模型。

## 下一批优先级

### P0：把 AI 变成可以核验的交付

- 配置真实供应商，在虚构需求上核验解析、出卷、失败降级、延迟和成本。现有测试使用受控传输/浏览器拦截，不代表供应商质量或可用性。
- 建立固定评测集：明确/缺失/冲突预算、授课方式否定表达、隐私内容和跨学段需求；出卷按不同学段/科目检查题意、唯一正确答案、解释与难度。结构校验无法证明答案正确，需要教师抽查。
- 发布公开前端与持久化演示 API，让评委可直接打开完整流程；当前只有仓库和本机启动方式。

### P1：围绕学习闭环继续增强

- 在用户主动选择下，把练习中的待讲解知识点交给老师，并明确哪些内容会被共享；目前仅带入知识点，不上传作答。
- 为资料补齐适教年级、专题能力及来源核验后，再考虑让这些字段参与推荐。当前年级只是摘要，不虚构适教资格。
- 前端预约/审核/举报翻页与全量统计接口接入，避免展示数量和真实总量混淆。

### P2：展示与终端收尾

- 主题统一、登录/匹配页残留蓝色、首页图示与筛选比例已在 Issue #25 跟踪；本批不覆盖该分工。
- 微信真机、合法域名和小程序交互地图；目前 H5 地图与小程序公共片区按钮的能力不同。
- 路演以“需求解析 → 地图匹配”和“笔记 → 练习 → 解析 → 找老师”两条路径呈现；不要把静态图示或固定示例描述为模型生成。
