## 家教入驻

复用 getMyApplication、saveApplicationDraft、submitApplication 和现有字段，不增加真实证件上传或新的后端字段。

- 未申请/草稿：允许填写及保存；提交前按现有约束反馈必填和格式错误。
- 待审核：只读，展示等待状态，提供刷新；不能修改或重复提交。
- 已拒绝：显示原因，允许修改后重新提交。
- 已通过：显示“修改并重新送审”流程。修改前说明保存会撤销公开展示并回到草稿；必须明确确认，先成功保存草稿，再提交审核。不能直接向只接受 draft/rejected 的提交接口发送 approved 状态。
- 保存成功、提交成功分别反馈；提交失败保留本次输入，并以服务端读取结果确定最新状态。
- 对缺失资料、长文本、合法价格边界、提交中重复点击及切换账号后的旧表单进行检查。

## 家教预约

工作台提供待确认、已接受、历史记录，可按状态筛选；历史覆盖拒绝、完成、取消，各组有空状态。使用现有服务返回的数据，不伪造全量分页。

| 当前状态 | 家教操作 | 结果 |
| --- | --- | --- |
| pending | accept | accepted |
| pending | reject | rejected |
| accepted | complete | completed |
| rejected / cancelled / completed | 无状态操作 | 只读 |

取消由家长执行；家教只能查看取消结果。接受、拒绝、完成前显示确认说明，取消确认不发送请求；请求中禁用同一记录的冲突操作。成功后以服务返回记录更新并刷新列表；409 提示状态已变化并重新获取，不能显示虚假的成功结果。API 不展示或保存真实联系方式。

## 管理员审核、举报与概览

- 列表区分待审核与处理结果，草稿不得误归为“已审核”；现有 API 若返回草稿，单独标识且无审核按钮。
- 详情展示现有必要的演示资料字段；仅 pending 可批准/拒绝。
- 拒绝原因去除首尾空格后不能为空，长度保持现有页面与接口兼容；确认后调用 reviewApplication。
- 已被另一管理员处理时提示刷新，不继续展示旧操作按钮。
- 举报按 open/resolved 分组，处理前确认，成功后更新状态；只实现现有“标记已处理”，不虚构封禁或处理备注接口。
- 概览显示“本次加载的待审/已通过/已拒绝申请数、待处理/已处理举报数”。申请接口最多返回 50 条，举报最多 100 条；明确非全平台统计，不把截断列表当成总量。全量统计/分页由 C 后续提供契约。
- 列表、详情各自具备加载、错误重试和空状态。

## 身份、权限与异步一致性

使用现有 currentSession、restoreSession、logout、businessService 和错误类型，不另存登录态、不在页面拼接令牌、不使用演示角色切换替代 API 登录。

B 的页面显示账户称呼、家教/管理员身份和 Mock/API 模式。提供返回首页、当前工作台、退出/切换账户入口，复用现有登录页。Mock 角色选择沿用原流程；API 切换先退出再用虚构账户登录，不把角色字符串当作授权。

- 未登录、错误角色、401、403、404 都给出适当引导或提示，不显示受保护数据和可操作按钮。
- 加载开始或身份变化时清理旧身份数据；请求完成时校验发起身份与请求批次，丢弃旧响应。
- 防止慢请求覆盖新列表、旧账号响应覆盖新账号数据、离开页面后的状态回写。
- 按钮隐藏只改善界面；最终角色、归属和合法状态由后端校验。
- 退出 API 失败时遵循共享会话层的实际清理行为，准确提示，不冒充服务端撤销成功。
