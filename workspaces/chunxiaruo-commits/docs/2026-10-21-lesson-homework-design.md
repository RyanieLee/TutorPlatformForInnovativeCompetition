# 课次、预习资料与作业提交：个人目录审核版设计

日期：2026-10-21。状态：设计和实施计划已由用户确认；个人目录审核版已实现，尚未集成主项目。

## 1. 已确认的目标与工作边界

用户负责家教端与管理员端，希望老师按每节课发布作业、发布预习课件，学生直接上传作业，老师查看上传结果。用户确认沿用现有“学生/家长”账号，并要求先在个人文件夹中创建，审核通过后再并入主项目。

- 本次所有新增或修改均位于 `workspaces/chunxiaruo-commits/`。
- 使用独立分支 `feat/chunxiaruo-lesson-homework-review`；不修改主分支，不改写现有工作分支，不自行合并。
- 主项目的 `src/`、`server/`、依赖、路由、公共契约本轮全部只读，包括原来允许编辑的家教、管理员页面。
- 设计、后续实施计划、功能源码、测试、预览工具与集成清单均在个人目录中交付。
- 后续集成需要单独审核具体差异；当前授权不包含将个人目录中的文件覆盖到主项目。
- 界面沿用中文及现有蓝白风格，适配电脑和手机网页。兼容现有 uni-app 构建方式；微信小程序真机验收不作为本次网页验收结果。

基线为 main 的 `5c189221bb80a6232e20c3902e550f1d867eb97b`。实施时记录固定基线，避免预览悄然使用后来变化的公共接口。

## 2. 现有代码事实与方案选择

已读取现有家教工作台、预约详情、家长预约列表、账号类型、BusinessService、数据库模型、API 契约及后端入口。现有角色为 `parent/tutor/admin`，前端将 parent 展示为“学生/家长”。预约记录包含 parentId、tutorProfileId、studentName，尚无独立学生账号或学生实体；当前没有课次、作业、附件模型，也没有真实文件上传接口。

方案 A（采用）：在预约下建立课次，复用预约所关联的老师与学生/家长账号，增加教学资料和作业数据。这样无需新增选课或师生绑定流程。

方案 B（暂不采用）：新增独立课程中心，再维护选课、课程成员和学生档案。该方案适合班级教学，但超出当前一对一家教流程。

本设计中的“一个学生”是某个预约中的学生称呼，不是通过名字推断的全局身份。一个家长账号有多份预约时，作业严格按 bookingId 区分，不能按 studentName 合并或授权。

## 3. 第一版用户流程

### 老师发布

1. 在家教工作台进入一个已接受的预约，打开“课次与作业”。
2. 新建课次，填写课次标题、上课时间、预习说明及作业要求；可以先保存草稿。
3. 上传预习课件，可选上传作业参考附件；填写可选截止时间。
4. 发布后，对应学生/家长可见。课次列表按上课时间、创建时间及 ID 稳定排序，不额外引入可重排课次编号。
5. 进入课次查看学生提交的文字说明、附件、提交时间和历史版本。

### 学生/家长查看和提交

1. 使用现有账号，在“我的预约”中进入相应预约的“课次与作业”。
2. 只看到已发布课次，查看预习说明、下载课件及阅读作业要求。
3. 选择作业图片或文件，填写可选说明；上传完成后点击“提交作业”。
4. 上传附件本身不算交作业；提交接口确认成功后才显示“已提交”。
5. 可以重新提交，新版本完整替换本次提交内容，历史版本保留。提交页面明确说明需要保留的附件必须包含在新版本中。

### 教师查看结果

每个课次显示“未提交”或“已提交”；超过截止时间仍可提交，并标记“逾期提交”。老师可以切换查看历史版本，图片可打开查看，PDF、Word、PPT 支持下载。第一版不承诺在线编辑或转换 Office 文件，也不新增评分、批注、自动批改、实时消息或管理员批改入口。

## 4. 课次与预约状态

- 只有预约所属老师可以创建、保存和发布课次，创建及发布时预约必须为 accepted。
- 草稿可修改；发布后内容锁定，避免学生按旧要求提交后被无记录地修改要求。内容修订能力不纳入第一版。
- 每个已发布课次必须有非空作业要求；预习说明及课件可选。截止时间若填写，须晚于本次发布时刻，并以服务端时间校验。
- accepted 和 completed 预约允许学生查看、提交与重新提交既有课次作业；老师标记预约完成不会阻断作业收交。
- 预约取消后双方仍可查看既有已发布资料和提交历史，但不能创建、发布或提交。pending、rejected 预约不能进入教学写操作。
- 草稿只对所属老师可见；学生访问草稿与访问他人记录一样返回 404。
- 截止时间采用 UTC 存储，界面按浏览器本地时间显示；服务端以收到有效提交的时间判断是否逾期。
- 标题 trim 后为 1–80 字，预习说明最多 10000 字，作业要求 trim 后为 1–10000 字，提交说明最多 2000 字。上课时间必填，日期均采用包含时区的有效 ISO 8601 时间。每份作业提交必须包含 1–5 个已完成上传的附件。

## 5. 数据结构与接口边界

在个人目录中的后端副本增加以下模型，复用原有 User、Booking、TutorProfile 关系：

| 模型 | 核心字段及约束 |
| --- | --- |
| Lesson | id、bookingId、title、scheduledAt、previewText、homeworkText、dueAt?、status(draft/published)、publishedAt?、createdAt、updatedAt、version；草稿更新和发布使用版本条件更新 |
| TeachingAttachment | id、lessonId、ownerId、purpose(preview/homework/submission)、originalName、mediaType、size、storageKey、createdAt；未绑定附件有过期时间 |
| HomeworkSubmission | id、lessonId、parentId、revision、requestId、note、submittedAt、late；同课次版本号唯一，同账户 requestId 唯一 |
| SubmissionAttachment | submissionId 与 attachmentId 的关系，记录每个版本的完整附件集合；已提交附件禁止改写或跨版本复用 |
| LessonAttachment | lessonId 与 attachmentId 的关系，区分预习课件和作业参考附件；发布时固定附件集合 |
| UploadQuota | userId、UTC 日期、已用字节数与预留字节数；按用户与日期唯一，原子预留配额后再接收文件 |

parentId 从已登录会话及预约关系取得。老师归属通过 Booking → TutorProfile → User 验证；不能比较登录用户 ID 与公开家教资料 ID。学生和老师均不能通过请求参数自行指定记录归属。

接口命名供审核使用，实施计划须保持一致：

| 方法与路径 | 功能 |
| --- | --- |
| GET /api/bookings/:bookingId/lessons | 双方按权限分页查询课次；学生只返回已发布课次 |
| POST /api/bookings/:bookingId/lessons | 老师创建课次草稿，支持 requestId 防止网络重试重复创建 |
| GET /api/lessons/:lessonId | 查询课次与已绑定资料；学生只看到已发布内容 |
| PUT /api/lessons/:lessonId | 老师保存草稿，携带 version；发布后拒绝更新 |
| POST /api/lessons/:lessonId/publish | 老师原子发布当前草稿、附件集合与版本；重复相同发布返回现有结果 |
| POST /api/lessons/:lessonId/attachments | 已鉴权 multipart 单文件上传，purpose 区分用途；上传前后均验证权限和课次状态 |
| GET /api/attachments/:attachmentId/content | 按归属鉴权读取附件；只允许读取本人未绑定附件或有权访问的已绑定附件 |
| GET /api/lessons/:lessonId/submissions | 查询该学生的提交版本列表，老师和对应家长可见 |
| POST /api/lessons/:lessonId/submissions | 学生提交完整新版本：requestId、note、attachmentIds；事务内验证归属与绑定关系 |

列表返回 `{data,meta:{total,page,pageSize}}`，页面提供加载更多。错误沿用现有 code；未登录 401、角色不符 403、越权记录 404、状态/版本冲突 409。附件超限 413，返回 INVALID 及明确中文提示。

提交重复请求使用同一 requestId 和相同规范化内容返回原版本；同 requestId 不同内容返回 409。版本分配与附件绑定在同一数据库事务中完成，独立并发提交不得覆盖历史版本。网络结果未知时保留 requestId，允许安全重试，不显示确定成功。

## 6. 文件保存与读取

审核版使用后端本地磁盘保存真实文件，元数据和归属写入审核用 SQLite 数据库。文件放在个人目录的私有运行目录中，不放 public，不提交 Git；重启后保留。预览数据库及上传目录作为一组持久数据保存，预览重建不能自动清空它们。

- 默认允许 JPG、PNG、WebP、PDF、DOCX、PPTX；界面明确列出格式，不笼统承诺所有 Word/PPT 格式。
- 单文件上限 20 MiB；预习课件、作业参考附件、每个作业提交版本各最多 5 个文件。客户端提示与服务端独立执行限制。
- 文件名只作显示，存储使用服务端随机标识；拒绝路径穿越、异常文件名和不匹配的文件内容。OOXML 文件按受限解析校验文档类型，不解压到公开路径。
- 上传按流处理；配置 multipart 大小限制，不把文件装入现有 32 KiB JSON 请求体，不修改其他 JSON 接口的限制。
- 老师仅能向 accepted 预约中的草稿上传预习或作业参考附件；学生仅能向 accepted/completed 预约中的已发布课次上传 submission 附件。所有其他状态与用途组合拒绝。
- 内容读取需要当前有效登录令牌和记录归属校验，不生成无需登录的永久公开 URL。下载文件名编码并设置 nosniff；图片只接受已验证格式。
- 网页通过带鉴权的请求获取 Blob 后打开图片/下载文件，退出登录、身份切换或组件卸载时释放对象 URL 并清除旧数据。
- 临时上传仅本人可读；发布或提交时验证附件属于当前用户、当前课次和用途，并在事务中绑定。不能引用他人的附件或已绑定到其他记录的文件。
- 失败、超限或中断的上传清理部分文件；未绑定临时附件在 24 小时后可由审核版清理命令删除。清理命令只扫描固定上传根目录并跳过已绑定记录，不能清理历史提交。
- 限制单账户每天成功上传量为 500 MiB，超额返回 429；上传计数持久化、并发预留和失败释放属于后端验收项。不能只依赖浏览器限额。

演示用单实例磁盘方案符合当前后端结构。后续如迁移对象存储，应保持现有附件权限契约；本次不新增云供应商绑定。

overlay 中使用主项目相对目录，便于逐文件审阅。涉及原项目文件时，只写个人目录中的对应副本。新的前端模块放审核应用的 src 内，避免已有的小程序构建不允许 src 外运行时 chunk 的问题。

预览准备脚本只读取固定基线，把完整应用生成在 `teaching/.local/review-app/`，再应用 overlay。所有依赖、生成文件、构建产物和运行数据留在个人目录；脚本不得安装到根项目、链接可写根文件、修改根锁文件或连接共享数据库。

脚本检查源基线与哈希，发现不一致或目标路径越界立即退出；默认不执行 root/server 数据库迁移，也不运行覆盖主项目的集成命令。需要一个真实可运行的 API 审核环境，让老师上传的资料在另一个浏览器的学生账号中可见；仅同浏览器 localStorage 的演示不满足验收。

审核应用复用现有账号模型、登录与角色检查，不新建学生身份体系。预览使用隔离数据库及现有初始化方式准备虚构演示账号；密码从本地环境读取，不写文档、Git 或前端源码。不复制真实学生资料到审核数据库。

## 10. 验收条件

1. 老师使用现有角色登录，对已接受预约新建、保存并发布课次；学生重新登录后能看到课件及作业要求。
2. 老师 A 发布的草稿、课件与学生 A 的提交，老师 B、家长 B、未登录请求及不相关管理员均无法读取；猜测附件 ID 不绕过权限。
3. 学生上传图片和文档后提交，老师在另一个浏览器登录能打开正确附件；验证真实文件内容，不能只检查文件名。
4. 截止后仍可提交且标记逾期；重新提交产生新版本，旧版本附件内容保持不变。
5. 断网、重复点击、重复 requestId、并发提交、身份切换、附件引用越权、超大/超量/错误格式均有确定结果且不泄露数据。
6. 预约取消时拒绝新的教学写入，保留已发布只读记录；预约完成后仍能收交既有作业。
7. 后端重启后课次、提交版本和文件仍可读取；失败上传、未绑定文件的清理不删除有效资料。
8. 运行现有业务回归、教学接口测试、类型检查与 H5 构建，完成电脑/手机网页的双角色浏览器流程；小程序仅有实际构建或真机结果时才记录通过。
9. 对比固定基线，提交差异的每条路径都以 `workspaces/chunxiaruo-commits/` 开头；主项目源码、路由、依赖、数据库和运行数据未被改动。
10. 交付启动说明、界面截图、真实命令与结果、未验证事项及逐文件集成清单。文档验收与功能验收分开记录。
